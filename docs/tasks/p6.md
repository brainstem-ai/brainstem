## 1. new packages/core/src/bitmap.ts — VersionedBitmap

Byte-array bitmaps, LSB0 ordering. No external libraries.

```ts
export interface CapabilityBitmap {
  catalogHash: string;
  bitLength: number;
  bytes: Uint8Array;     // length = ceil(bitLength/8), unused final bits ZERO
}
```

- `createBitmap(catalogHash, bitLength)` (zeroed), `clone`, `setBit(bm, i)`, `clearBit(bm, i)`, `getBit(bm, i)`, `popcount(bm)`, `isEmpty`, `isFull`
- set algebra returning NEW bitmaps: `union`, `intersection`, `difference`, `equality`
- `toIds(bm, catalog: {id: string}[]): string[]` / `fromIds(ids, catalog, catalogHash): CapabilityBitmap`
- Serialization: `encodeBitmap(bm): { catalogHash, bitLength, encoding: "base64-lsb0", data: string }` and `decodeBitmap(enc): CapabilityBitmap`
- ALL ops validate: index < bitLength (throw RangeError), catalogHash equality between operands (throw on mismatch), byte length consistency, padding bits zero on decode (throw on nonzero padding), bitLength > 0 (empty catalog: bitLength 0 allowed for createBitmap with bitLength 0 — ops on it are no-ops; document).
- NEVER use one JS integer as the bitmap; no shifts beyond 32-bit words — bytes only.

## 2. new packages/core/src/capabilities.ts

```ts
export interface CapabilityDescriptor {
  id: string;                  // "tool:read", "skill:frontend-debugging"
  kind: "tool" | "skill";
  version: string;
  description: string;
  useWhen: string[];
  avoidWhen: string[];
  requires: string[];          // stable capability IDs
  alwaysAvailable: boolean;
  contentHash: string;         // hashAction over schema/instructions
}

export interface CapabilityCatalog {
  catalogHash: string;
  entries: CapabilityDescriptor[];   // sorted by id, frozen
}

export function compileCatalog(descriptors: CapabilityDescriptor[]): CapabilityCatalog
```

- compileCatalog: reject duplicate ids; reject requires referencing unknown ids; reject dependency cycles (DFS); sort by id (lexical, stable); catalogHash = hashAction over canonical descriptor list + ordering + schema version string "capcat/1".
- Selection masks (separate named masks, same bitmap mechanics, distinct namespaces so capability and section bitmaps can't mix — bitmap ops take a `namespace` string embedded in... simplest: namespace is part of catalogHash prefixing convention: capability catalogs hash with "capcat/1", section manifests (F1) with "sect/1" — enforce via `compileCatalog(..., namespace)` parameter defaulting "capcat/1"):
- `interface WorkingSet { available, baseline, explicit, evaluated, recommended, active: CapabilityBitmap }` + `computeActive(catalog, working, opts)`:
  - active = dependency-closed union of baseline ∪ explicit ∪ pinned ∪ recommended∩available, minus unavailable
  - a capability whose `requires` aren't all active is REJECTED: optional ones dropped (record why), explicit ones reported as unmet
  - return { active, unmetExplicit: string[], dropped: {id, reason}[] }
- Pinned set: `string[]` passed in opts (workflow pins, P7 will manage it).
