Goal: stable IDs so interleaved activity is attributable to the correct task, tool call, judgment, and decision — no "last matching event" heuristics. Schema v2 for the journal. TDD. No other changes (do NOT touch decide* policy logic — that is P4/P5).

## 1. new packages/core/src/evidence.ts

```ts
export interface TaskState {
  id: string;            // e.g. "task_01J..." (crypto.randomUUID or ulid-style, your choice, consistent)
  revision: number;
  objective: string;
  updates: string[];     // subsequent user constraints/updates, never approval responses or harness notices
}

export interface ToolObservation {
  toolCallId: string;
  tool: string;
  argsSummary: unknown;          // validated args, small (command/path); hash large bodies
  status: "ok" | "error" | "timeout" | "cancelled" | "blocked";
  exitCode?: number;
  durationMs: number;
  excerpt: string;               // bounded (2_000 chars) evidence actually observed
  truncated: boolean;
}

export function hashAction(input: unknown): string;   // stable sha-256 over canonical JSON
```

## 2. journal.ts — schema v2

Rewrite JournalEvent as a versioned union. Every event gains: `v: 2`, `sessionId`, and where applicable `taskId`, `turnId`, `toolCallId`:

- `session_start { v, sessionId, ts, trust, policySnapshot: Policy }` (policySnapshot = the full Policy object; also add `policyHash: hashAction(policy)`)
- `task_start { v, sessionId, taskId, ts, objective }` / `task_update { v, taskId, revision, ts, text }`
- `turn_start { v, sessionId, taskId, turnId, ts }` / `turn_end { v, turnId, ts, modelCalls, durationMs }`
- `reflex { v, sessionId, taskId, turnId, judgmentId, ts, reflex, subject, status: "completed"|"unavailable"|"cancelled", state, questions, result | null }` — judgmentId is new; when status !== "completed", `result` is null and `reason` (string) explains. Keep full question bodies.
- `decision { v, judgmentId, ts, reflex, action, reasons, staticVerdict?: "deny"|"ask"|null, approvalId?: string }` — decision now references its judgment by ID. Static-only decisions (floor, no Jev call) have NO judgmentId (do not manufacture one).
- `approval { v, approvalId, ts, status: "requested"|"approved"|"denied"|"cancelled"|"invalidated", taskId, toolCallId, actionHash, reasons }` (recorded shape only; lifecycle is P3)
- `tool_observation { v, toolCallId, turnId, ts, observation: ToolObservation, deliveredExcerpt: string, deliveredTruncated: boolean, deliveredWhy?: string }` — what was observed AND what was actually delivered to the model, separately.
- `llm_call { v, turnId, ts, model, durationMs, usage: {input, output, cacheRead, cacheWrite, costTotal | "unknown"} , firstTokenMs? }` — actual usage; unknown cost stays "unknown", never 0.
- `session_end { v, sessionId, ts, reason: "normal"|"error", error?: string }`
- `artifact` events: `artifacts { v, artifactId, ts, toolCallId, contentHash, captureComplete: boolean, byteCount, presentedViewHash?, sectionManifestHash? }` — recorded shape for F0/F1; harness can emit minimal ones now.
- Measured spans: add a `spans` object where natural (turn_end: { jevMs, approvalWaitMs, toolMs, modelMs }) — measured in harness code with performance.now; do not fake precision.

Keep `openJournal`/`loadJournal`/`appendJournalEvent` signatures working: loadJournal must accept v2 records and throw a clear error on unknown schema versions; appendJournalEvent stays mkdir-safe for standalone use; `openJournal` mkdirs ONCE at open and its returned Journal.append must NOT re-mkdir per append.

## 3. new packages/cli/src/session.ts

A `SessionRecorder` class that owns ID allocation + counters (all in code, exact):
- `new SessionRecorder(journal, cwd)` → allocates sessionId, appends session_start.
- `startTask(objective)` → TaskState + task_start; `updateTask(text)` → revision++, task_update.
- `beginTurn()` / `endTurn(extraSpans?)` → turnId, turn_start/turn_end.
- Counters + accessors: modelCalls, totalCost (sum of known costs only — unknown stays unknown), repeatedActionCounts (Map<actionHash, count>), elapsedMs.
- `recentActivity(n)` → array of short factual lines from the last n tool observations, e.g. `bash: npm test (exit 1, 2.1s)` or `write: src/auth.ts (12 lines)` — ACTUAL commands/paths, not placeholders.

## 4. harness.ts — wire it

- Create SessionRecorder at harness creation; startTask on prompt (same objective reused if identical text, else new task — explicit: a different string starts a new task revision via updateTask if it reads as a constraint update? NO — keep simple for P2: every prompt() with different text starts a new task; identical text continues).
- beforeToolCall: allocate toolCallId (from context toolCall.id), emit tool_call-compatible events via observations; static-floor deny → tool_observation with status "blocked" and a decision WITHOUT judgmentId.
- afterToolCall: build ToolObservation from result + execution metadata (status/exitCode/durationMs/truncated — tools.ts details already carry exit/truncated/status from P1), emit tool_observation with delivered excerpt (what afterToolCall returns/leaves).
- Reflex engine calls stay the same BUT engine.recordReflex/recordDecision must accept and propagate a judgmentId: engine asks its journal for an id (add `nextJudgmentId()` to the engine deps or pass an idFactory — smallest change: engine constructor takes optional `makeId: () => string`).
- Gate "blocked" results: tool_observation status "blocked".
- summarizeMessages for pulse/steer: use recorder.recentActivity(n) facts plus last assistant text — real commands, not placeholders.
- session_end on process error path where possible (try/finally around main flows is fine).
