# Task F2: Integrate Focus once per new result, roll out conservatively

Repo: brainstem (bun + TS). Baseline: F1 (`packages/core/src/output-sections.ts`, `output-focus.ts`, `ReflexEngine.focus`), F0 (`ArtifactStore`, `sliceByLines`), P8 (`prepareNextTurnWithContext`, capability wiring — unrelated to this unit, do not touch). All tests green.

Goal: wire F1's mechanism into the actual presented-view pipeline in `harness.ts`'s `afterToolCall`, replacing the fixed-10-line-truncation fallback with a Focus-driven one, behind an explicit rollout mode. This is the one unit in the plan that touches the live tool-result path — F1 was deliberately kept pure `packages/core` so this integration could be reviewed on its own.

Implemented directly (no delegated agent, no separate worktree) since there is no parallel work to isolate — a feature branch in the existing checkout is enough.

## 0. A real defect this unit also fixes

Today, `afterToolCall` sends `fullText.slice(0, 8000)` to `engine.observeToolResult` (sanitize/verify) regardless of what the presented view actually bounds it to. For any capture over the 10-line truncation threshold but under 8,000 raw characters — the common case — sanitize is judging content the model was never shown, and a "review"/"mismatch" note can reference material invisible to the agent. The plan's own words for this unit are explicit: *"capture → applicability/full view or focus → exact final-view sanitize + verify → commit."* Fix this as part of building `present.ts`: sanitize's `content` must come from the same bounded value that becomes `baseView`, never from a second independent slice of the raw capture.

This is safe to change: every existing test with a capture short enough that `fullText.slice(0,8000) === fullText` is unaffected (baseView equals fullText too, in the no-truncation case), and the one existing large-output test (`recovery.test.ts`'s 50-line bash capture) doesn't assert on sanitize's exact input length or content — its mock branches only on which question keys are present.

## 1. packages/cli/src/output/present.ts (new)

Pure, synchronous, no I/O, no Jev call — this module only shapes text from an already-computed `FocusDecision`. The Jev call itself stays in `harness.ts` (§3), matching how the rest of the harness keeps `ReflexEngine` calls at the call site and pushes only the shaping logic into a testable pure module (compare `change-summary.ts`).

```ts
export type FocusRolloutMode = "off" | "shadow" | "on";

export const PRESENTED_LINE_CAP = 10;          // moved here from harness.ts — single source of truth
export const FOCUS_PRESENT_BUDGET_CHARS = 4_000;  // decoupled from EXCERPT_CAP (a different, pre-existing cap for stored observation excerpts)

export interface PresentedView {
  text: string;
  truncated: boolean;
  presentedAs: "naive" | "focus_full" | "focus_select" | "focus_compute_or_retrieve";
}

export function presentNaive(fullText: string, artifactId: string, lineCap?: number): PresentedView

export function presentFocused(
  fullText: string,
  artifactId: string,
  manifest: SectionManifest,
  decision: FocusDecision,
  lineCap?: number,
): PresentedView

export function presentArtifact(
  fullText: string,
  artifactId: string,
  opts: { rollout: FocusRolloutMode; manifest?: SectionManifest; decision?: FocusDecision },
): PresentedView
```

- `presentNaive`: exactly today's inline logic — `sliceByLines(fullText, 1, lineCap ?? PRESENTED_LINE_CAP)`; if `slice.totalLines > lineCap`, return the truncated text plus the existing notice string (`"[brainstem] capture archived as artifact <id>; showing lines 1-<lineCap> of <N> — use read_output or search_output to recover the omitted lines."`), `truncated: true`, `presentedAs: "naive"`; otherwise the full text, `truncated: false`.
- `presentFocused` branches on `decision.mode`:
  - `"full"` → identical output to `presentNaive` (same text, same notice) — `presentedAs: "focus_full"` for journaling purposes only; the delivered text must not differ from the naive path for this mode, per `FocusDecision`'s own contract that an empty `selected` bitmap under `"full"` means nothing was assessed, not that nothing is shown.
  - `"select"` → join the sections where `getBit(decision.selected, idx)` is true, in manifest order, with a blank line between sections; append a receipt line: `"[brainstem] focus: showing <k> of <n> sections (<selectedChars> of <totalChars> chars) relevant to the task; archived as artifact <id> — use read_output or search_output to recover the rest."` Only emit the receipt (and set `truncated: true`) when `k < n`; if every section was selected, no notice, `truncated: false`. If `k === 0` despite `mode === "select"` (should not happen given `decideFocusMode`'s own logic, but defend against it), fall back to `presentNaive` — never present empty content as a successful selection.
  - `"compute_or_retrieve"` → `presentNaive`'s text and truncation flag, plus one appended line distinct from the naive notice: `"[brainstem] focus: no single section was clearly relevant to the task — use search_output with a specific pattern, or read_output for a range, to find what you need."` `presentedAs: "focus_compute_or_retrieve"`.
  - Do not expose `decision.scores` or `sectionReasons` in any presented text — the plan is explicit that only the agent-actionable receipt (coverage, recovery path) belongs in the delivered content, not internal scores.
- `presentArtifact`: `opts.rollout === "off"` or `opts.decision`/`opts.manifest` undefined → `presentNaive`. Otherwise → `presentFocused`. This is the only function `harness.ts` calls directly.

## 3. harness.ts wiring (`afterToolCall`)

Insert between the existing artifact-capture block and the existing `obs`/`baseView` construction. Exact sequencing matters — read the current function before editing; do not reorder the artifact capture (must stay first) or the final `journal.append({t:"artifacts",...})` (must stay last, since it records `presentedViewHash` from the final `deliveredExcerpt`).

1. After `obs` is built and `recorder.recordAction(...)` runs (unchanged), compute the bounded `intent` string once — hoist the existing `const intent = \`${toolCall.name} ${JSON.stringify(toolCall.arguments)}\`` out of the later `if (!isError && fullText.trim())` block so both sanitize and focus can share the identical string; do not compute it twice with slightly different phrasing.
2. If `artifact` exists and `options.focusMode !== "off"`:
   - `const manifest = splitIntoSections(artifact.artifactId, fullText);`
   - `const focusDecision = await timedJev(() => engine.focus({ task: taskText(), command: actionLabel(toolCall.name, toolCall.arguments), intent, outcome: obs.status, recentFindings: recorder.recentActivity(5), manifest, budgetChars: FOCUS_PRESENT_BUDGET_CHARS }));`
   - `options.onReflex?.(render("focus", focusDecision.mode, focusDecision.reasons));`
   - Both `manifest` and `focusDecision` stay `undefined` when `focusMode === "off"` or there is no `artifact` (recovery-tool results, errors, empty output) — Focus never runs on `read_output`/`search_output` results, matching F0's existing "skip artifact capture for recovery tools" boundary; do not add a second capture/focus path for them.
3. Compute the presented view: `const view = artifact ? presentArtifact(fullText, artifact.artifactId, { rollout: options.focusMode === "on" ? "on" : "off", manifest, decision: focusDecision }) : { text: obs.excerpt, truncated: obs.truncated, presentedAs: "naive" as const };` — note `"shadow"` deliberately maps to the `"off"` rollout argument here: Focus still ran and its decision is journaled (step 5), but the presented text is exactly the naive view, matching *"shadow: records selections and costs but presents the original."*
4. `baseView = view.text; deliveredTruncated = view.truncated;` — replaces the current inline `sliceByLines`/notice block entirely; delete that block, it now lives in `present.ts`.
5. In the existing `if (!isError && fullText.trim())` sanitize/verify block, change `content: fullText.slice(0, 8000)` to `content: baseView.slice(0, 8000)` (§0's fix). Everything else in that block — the `notes`/`deliveredWhy` construction, the `${notes.join("\n")}\n\n${baseView}` composition — already correctly uses `baseView` and needs no change.
6. Extend the `"artifacts"` journal event (only emitted when `artifact` exists, unchanged condition) with: `...(focusDecision !== undefined ? { focusRollout: options.focusMode === "on" ? "on" as const : "shadow" as const, focusMode: focusDecision.mode, focusStatus: focusDecision.status } : {})`. `sectionManifestHash` (already a field on this event from F0) is now actually populated: `...(manifest !== undefined ? { sectionManifestHash: manifest.catalogHash } : {})`.

## 4. Journal schema (packages/core/src/journal.ts)

Add three optional fields to the existing `"artifacts"` event (do not touch any other event type):

```ts
focusRollout?: "shadow" | "on";                              // absent entirely when focusMode is "off" — no Focus call was made
focusMode?: "full" | "select" | "compute_or_retrieve";        // the FocusDecision's own mode, distinct from the rollout config
focusStatus?: "ok" | "partial" | "unavailable";
```

Naming note: `focusRollout` is the harness's configured rollout setting for *this* call (never `"off"` on this event, since the event only gains these fields when Focus actually ran); `focusMode` is F1's `FocusDecision.mode` output. Keeping these as two distinctly-named fields (not overloading one `mode` field for two different concepts) avoids exactly the kind of ambiguity P7's `select__`/`focus__` id-prefix conventions were designed to prevent.

## 5. Tests

`packages/cli/test/present.test.ts` (new, pure unit tests, no harness/Jev involved):
- `presentNaive`: short content → full text, `truncated: false`; content over the line cap → truncated text + exact notice string, `truncated: true`.
- `presentFocused` `"full"` mode → byte-identical output to `presentNaive` on the same input.
- `presentFocused` `"select"` mode: construct a `SectionManifest` and a `FocusDecision` with 2 of 5 sections selected → output contains exactly those two sections' text in manifest order, the receipt line names "2 of 5", `truncated: true`. All 5 selected → no receipt line, `truncated: false`.
- `presentFocused` `"select"` mode with an empty `selected` bitmap (defensive case) → falls back to naive output, not empty content.
- `presentFocused` `"compute_or_retrieve"` mode → naive text plus the distinct search-guidance line, and that line's wording differs from `"full"`'s notice (assert the two strings are not equal, so a future edit can't accidentally merge them).
- Internal scores never appear in any presented text — build a `FocusDecision` with recognizable score values (e.g. `0.87654`) and assert the presented string never contains that substring.
- `presentArtifact`: `rollout: "off"` always returns `presentNaive`'s output even when a `"select"`-mode decision is supplied — proves shadow/off can never leak a focused view.

`packages/cli/test/harness.test.ts` / `runtime-contract.test.ts` (extend):
- `focusMode: "off"` (the default, and the only mode most existing tests use) — assert zero `"focus"` reflex events are journaled for a large capture, and the presented text is byte-identical to what `main` produces today (regression pin for the refactor in §3).
- `focusMode: "shadow"`: a large capture with a mocked Jev focus response selecting one section — assert the delivered tool-result text is still the naive truncated view (not the focused one), while the journaled `"artifacts"` event carries `focusRollout: "shadow"`, `focusMode: "select"`.
- `focusMode: "on"`: same setup — assert the delivered text now contains only the selected section's content plus the receipt line, and does *not* contain content from unselected sections.
- sanitize sees the bounded view, not the raw capture: construct a large benign capture whose *unselected* tail contains a string that would trip the hostile-content mock if seen (e.old., an "IGNORE ALL PREVIOUS INSTRUCTIONS"-style marker placed only past the naive 10-line truncation boundary or outside the focus selection) — assert sanitize's recorded judgment state does not include that string, proving the §0 fix landed (spy the mock's received `state.content`, do not just check the final delivered text).
- `focusMode !== "off"` on a `read_output`/`search_output` result → still zero focus reflex events (no artifact means no focus call), confirming recovery tool results are never re-focused.

`packages/core/test/journal.test.ts` (extend): the three new optional fields on `"artifacts"` round-trip through `loadJournal`; an event without them (legacy shape) still parses.
