Repo: brainstem (bun + TS). packages/core owns types/providers/engine/policy. Baseline: journal v2 (reflex events carry status "completed"|"unavailable"|"cancelled").

Goal: Jev becomes a validated, bounded, failure-tolerant dependency with explicit fallbacks per reflex. TDD. This unit is core-only (no harness changes except wiring budgets/signals at the end).

## 1. types.ts — ask contract + judgment envelope

- `SystemOne.ask(state, questions, options?)` where options: `{ signal?: AbortSignal; deadlineMs?: number }` — implementers must honor deadline (reject with a typed error when exceeded) and signal.
- New discriminated union:
```ts
export type JudgmentOutcome =
  | { status: "completed"; result: AskResult }
  | { status: "unavailable"; reason: string }
  | { status: "cancelled"; reason: string };
```
- Keep AskResult unchanged.

## 2. providers/jev.ts + mock.ts

## 3. new packages/core/src/validation.ts

`validateAnswers(questions, rawAnswers): Record<string, Answer>` — throws JevUnavailableError on any violation:
- every question id present in answers; unknown answer ids rejected (log-free, throw)
- type matches question type; noul ∈ [0,1] finite; score within [0, criteria.length-1] finite; choice ∈ criteria keys
- probabilities: object, finite values in [0,1] (optional field tolerated missing)
- confidence: finite in [0,1] REQUIRED on choice/score answers — a missing confidence is a validation failure, NOT a default
- Fused reflex groups: validateAnswers takes an optional groups map `{ groupName: id[] }` and returns per-group validity: a broken verify group must not invalidate a valid sanitize group — expose `validateGroups(questions, raw, groups): { groups: Record<string, Record<string, Answer> | null>, errors: Record<string, string> }`.

## 4. engine.ts — consume JudgmentOutcome

- engine.gate/sanitize/observeToolResult/pulse/steer: ask() now returns JudgmentOutcome.
  - completed → validate → proceed as today (journal reflex status "completed")
  - unavailable/cancelled → journal reflex with status + reason, result null → decide via FALLBACK table (below), journal decision with fallback reason
- Fallback table (implement as a switch on reflex name; config lives in policy):
  - gate: static floor verdict; if floor null → "ask" with reason "judgment unavailable"
  - sanitize: return action "block" with reason "sanitizer unavailable — content withheld" (NEVER pass unchecked content)
  - verify: { action: "ok", reasons: ["verification unavailable — result not verified"] } — but the decision event must record status unavailable so callers know it is NOT a positive verification. Change VerifyDecision to include `verified: boolean` (true only when completed) — update harness usage so a non-verified result gets the same annotation text as mismatch-lite ("[brainstem] verify: unavailable — result not verified").
  - pulse: { action: "continue", reasons: ["pulse unavailable"] } (budgets still enforced deterministically)
  - steer: { tier: "frontier", reasons: ["steer unavailable — using main model"] }
- Malformed answers (validation failure) count as unavailable, never as data.

## 5. policy.ts + circuit breaker (new packages/core/src/circuit-breaker.ts)

- Policy additions (defaults): `{ jev: { deadlineMs: 1500, retries: 0, breaker: { threshold: 3, cooldownMs: 10000, probe: 1 } } }` — `retries` stays 0 this unit; the field exists for P10.
- CircuitBreaker class: `canRequest(): boolean`, `onSuccess()`, `onFailure()`. Opens after threshold consecutive failures; after cooldown allows `probe` request(s); success closes; user CANCELLATION is never a failure. Wire it into jev provider via an optional decorator `withCircuitBreaker(provider, breaker)` (new provider wrapper in providers/jev.ts): when open, ask() returns unavailable immediately with reason "circuit open".
- Unit tests for the breaker incl. cooldown probe behavior and cancellation exclusion.

## 6. Deterministic budgets (core)

Limits in policy: `{ budgets: { maxModelCalls?: number, maxElapsedMs?: number, maxSpendUsd?: number } }` (undefined = unbounded).
