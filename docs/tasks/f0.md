# Task F0: Bounded output artifacts and recovery tools

Repo: brainstem (bun + TS). Baseline: journal v2 (artifact event shape exists), tools.ts with bash capture (P1: bounded, truncated flag, status), harness with afterToolCall.

Goal: never lose command output. Original captures persist as artifacts; anything omitted from the presented view stays recoverable WITHOUT rerunning the command. TDD.

## 1. new packages/core/src/artifacts.ts

```ts
export interface ArtifactMeta {
  artifactId: string;
  toolCallId: string;
  tool: string;
  commandOrTarget: string;      // command for bash, path for read/write
  contentHash: string;          // sha-256 of full capture
  byteCount: number;
  lineCount: number;
  captureComplete: boolean;     // false when capture hit the byte limit
  createdAt: number;
}
export interface ArtifactRecord extends ArtifactMeta { streams?: { stdoutBytes: number; stderrBytes: number } }
```
- `ArtifactStore` interface: `put(record: ArtifactMeta, content: string): void`, `get(id): { meta: ArtifactMeta; content: string } | null`, `list(): ArtifactMeta[]`.
- Free functions: `sliceByLines(content, startLine, lineCount): { text, startLine, endLine, totalLines }` (1-indexed, inclusive), `searchContent(content, pattern, limit): { matches: { line: number; text: string }[]; totalMatches: number; truncated: boolean }` (regex construction wrapped in try/catch → invalid pattern = typed error, bounded to first 5_000 lines scanned... no: search ALL lines but cap returned matches at limit; cap regex work by input size 1MB).

## 2. new packages/cli/src/output/artifact-store.ts

- Local FS store rooted at `<sessionDir>/artifacts/` (sessionDir derived from journalPath's directory). One JSON metadata file + one raw content file per artifact (`<id>.json`, `<id>.txt`).
- Session limits: max 50 MB total, max 200 artifacts; LRU eviction by createdAt (evicted = content deleted, meta kept with `evicted: true`; recovery of evicted = explicit "expired" outcome).
- put() is synchronous append-and-rename style (write temp, rename) to avoid torn files.

## 3. new packages/cli/src/output/recovery-tools.ts — two ALWAYS-AVAILABLE tools

- `read_output({ id, startLine?, lineCount? })`: defaults startLine 1, lineCount 200, max 2_000. Response: the exact lines with a header `artifact <id> lines X-Y of N (complete|truncated-capture|evicted)`. Unknown id / evicted / empty → distinct explicit messages (never a bare "no output").
- `search_output({ id, pattern, limit? })`: defaults limit 50. Response: matches with line numbers + total count + truncated flag.
- Both are read-only, `executionMode: "parallel"`, alwaysAvailable (registered in the registry as baseline tools `tool:read_output`, `tool:search_output`).
- Response content flows through the normal sanitize/verify path like any tool result — no bypass.

## 4. harness.ts integration

- In afterToolCall (BEFORE sanitize): for bash/read/write/grep/glob results, store the FULL result text as an artifact (before any override), journal the `artifacts` event (v2 shape: artifactId, toolCallId, contentHash, captureComplete = !details.truncated, byteCount).
- bash: content = combined stdout+stderr as captured; captureComplete = !truncated flag from tools.ts details. Mark stream split if available.
- The presented view (what the model sees) may be the full capture today; still record `presentedViewHash` in the artifact event (= hash of delivered excerpt) — F1 will diverge these.
- Recovery tool executions also get observed (sanitize) but their artifacts are NOT stored (avoid recursion): skip artifact capture for read_output/search_output.
